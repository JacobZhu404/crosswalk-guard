# 违章11 跨环境结果差异 — 权威对照说明

> 结论先行：**违章11 的正确判定是「违章确认」，F1=0.941 是基准**。本机（Win x64）出现的「待复核 / F1=0.875」是**平台数值差异导致的单帧误判**，不是代码退步、不是版本问题，有 GT 真值为证。
>
> 本文由原始开发环境（Mac arm64）逐帧对照 + 人工标注真值（canonical GT）交叉验证产出，作为此后任何环境复现差异的权威依据。

---

## 1. 现象

| 环境 | 全 11 视频结果 | 违章11 判定 |
|---|---|---|
| 原始开发环境（Mac arm64, torch 2.13.0 / ultralytics 8.4.93） | **F1=0.941　P=1.000　tp=8 fp=0 fn=1　误罚=0** | **违章确认** ✅ |
| 新接手环境（Win x64, 全新安装） | F1=0.875　P=1.000　tp=7 fp=0 fn=2　误罚=0 | 待复核 |

其余 10 个视频两环境**逐条一致**（含负例 01/10 零误报、违章09 命中、违章04 双方都漏）。差异**只在违章11 一个视频**。

## 2. 根因：钉死在单帧（22.4s）

违章11 的绿灯违章相位是 15–28.4s。门控规则：**绿灯需连续 ≥6.0s 才判「确认」**，否则降级「待复核」。

逐帧观测对照（钩住真实 `observe()` 取值）：

| 时刻 | 原始环境（Mac） | 新环境（Win） |
|---|---|---|
| 22.4s 这一帧 | obs=**green**（conf 0.59） | obs=**red** |
| 连续绿灯段 | **[15.86, 28.26] = 12.40s** ≥ 6.0s | 被 22.4s 切断为 5.33s < 6.0s |
| 判定 | **违章确认** | 待复核 |

**一帧的判决翻转了整个事件。** 新环境在这一帧，先验 ROI 内采到的是远处车辆的刹车灯（红），而非信号灯。

## 3. 谁对？GT 真值说了算 —— 原始环境正确

人工标注的 canonical 真值（`datasets/gt/light_canonical_gt.json`）对违章11 的覆盖：

```
t=18s governing灯=green,green,green
t=20s governing灯=green,green
t=22s governing灯=green,green   ← 关键帧，真值明确是绿灯
t=24s governing灯=green,green
t=26s governing灯=green,green
t=28s governing灯=green,green
```

证据帧见本目录：

- `违章11_t22_4s.jpg` —— 绿框=GT 标注的行人信号灯位置，画面清晰可见**绿色行走小人 + 绿色倒计时数字**；同时可见多辆车停在斑马线上、行人正过街，是真实违章场景。
- `违章11_t20_0s.jpg` / `违章11_t24_0s.jpg` —— 前后帧佐证灯色全程为绿。

**∴ 22.4s 真值 = 绿灯。原始环境判「绿→确认」与 GT 一致 = 正确；新环境该帧把绿采成红 = 误判。F1=0.941 为准。**

## 4. 为什么不是版本问题、改代码也修不了

接手方已做充分排除实验（均不改变结果）：

- ❌ ultralytics 版本：钉回原始验证版 8.4.93，落盘 CSV 逐字节一致，仍 0.875。
- ❌ opencv 版本：降级 4.14 重跑，结果不变。
- ❌ 先验 ROI 位置：GT 三个真灯框全在 ROI 内，像素验证通过。
- ⏳ torch 版本：**无需再追**——差异源是 CPU 架构（Mac arm64 vs Win x64），换 torch 版本改变不了架构。

**真正源头**：YOLOv8n 在该单帧、置信度贴阈值（灯框 conf≈0.27 vs 阈值 0.25）时，不同 CPU 架构的浮点数值路径产生亚像素/亚阈值抖动，恰好把这一帧推到阈值两侧。这是**环境固有差异**，改代码无法消除，且项目红线禁止改 `src/`。

## 5. 对接手方的指引

1. **这不是退步**：P=1.000、误罚=0（零误罚铁底线）在两个环境都稳固，核心逻辑完好。差异仅是召回少 1 个视频，且该视频真值已确认为违章。
2. **出交付物时**：可按本机真实结果渲染，但须注明「违章11 真值为违章确认（有 GT 为证），本机因平台数值差异在单帧误判为待复核」，避免误导为系统退步。
3. **若要彻底消除此类单帧抖动**：需对贴阈值帧加时序平滑 / 多帧投票（属判定逻辑改动，须项目所有者批准）。**不要擅自调 #3 门控的 6.0s 阈值**——它是精心校准的（落在负例 01 假绿 3.10s 与真绿之间），动它会破坏其他视频。
4. **复现基准**：严格用 `pip install -r requirements.txt`（已 pin 版本）。即便如此，跨 CPU 架构的单帧抖动仍可能存在——这是已知且已解释的，以本文为准。
