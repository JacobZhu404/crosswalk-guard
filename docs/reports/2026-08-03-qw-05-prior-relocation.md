# 违章05 prior 重定位可救性验证(qw, 只读)

> 三臂对照(C/F/O)各调 `_sample_prior_color`, 量颜色正确率 + 假绿数。为第③步 prior 重定位 de-risk。

> `_sample_prior_color` 返回颜色字符串(非框), 是独立于候选/选灯的并行信号路径。

> prior_roi_px=160, 走 2x 自适应扩展。GT 仅作 Arm O 的诊断 oracle, 非生产路径。


## 三问裁断

Q1 可救性上界: Arm O 颜色正确率 15/30 = 50.0% <80% → 即便正确定位, 该灯颜色也难采, 重定位救不了, 需另想。

Q2 固定够不够: Arm F(16/30) vs Arm O(15/30), 差 -1 → 固定 vs 逐帧**无意义**: 两者都 ≈50%, 因为瓶颈不是位置而是 _sample_prior_color 方法本身(160px ROI 捕获过多环境绿, 见根因分析)。

Q3 假绿是否被杀: Arm C=15 → Arm F=14 → Arm O=15 → Arm O 残余 15 假绿(正确位置 ROI 仍混入红相位绿干扰)


## 根因分析: oracle 位置为什么也救不了

Arm O(oracle 逐帧 gov 中心) 的 ROI(160px) 内绿/红像素占比:

- **红灯帧**(15帧): g_frac 均值=14.6%, r_frac 均值=3.0%
  → 绿像素是红像素的 **4.8x**, 远超 `_sample_roi` 的 g_frac>r_frac×1.3 判绿阈值
- **绿灯帧**(15帧): g_frac 均值=15.5%, r_frac 均值=0.2%
  → 绿像素是红像素的 62.4x

**结论**: 160px ROI 即使正确定位在 gov 灯上, 仍捕获大量环境绿(树叶/建筑/反光)。
红灯帧的环境绿是信号红的 4.8x, `g_frac>r_frac×1.3` 恒成立 → **永远判绿**。
prior 重定位(改位置)救不了 05; 瓶颈在 `_sample_prior_color` 的 ROI 太大 + 像素计数投票机制,
不是 prior 位置。方向: 缩小 ROI(如 40-60px 聚焦灯体)或改走候选路径(connected components 空间过滤)。

## 方法学

- 三臂均调 `det._sample_prior_color()`(含 2x 自适应扩展), 口径与生产 observe() 的 prior 直采一致。

- Arm O prior = 该帧 gov box 中心(GT), 仅诊断 oracle, 非生产路径(红线: GT 不进推理)。

- g_frac/r_frac = g_n/r_n ÷ ROI 像素面积(含边界裁剪); 若紧 ROI 无色则用扩展 ROI 面积。
