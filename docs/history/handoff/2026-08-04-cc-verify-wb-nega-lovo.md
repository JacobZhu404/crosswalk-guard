## 1. 05/09 归因(cc 亲查缓存, 修正了自己的初判)
- **违章05(seed2)**: 15 gt_green 帧全 had_cands, best_color=green **11/15**, 但置信度<0.30 被弃权 → 漏绿14。**不是候选不存在, 是判别器"候选在、不敢认"**(我初判"候选缺失"被数据修正)。→ 05 该不该扣漏绿, 取决于口径是"产品级(漏就算漏)"还是"判别器级(候选ceiling不算判别器的账)"——**这是口径决策, 归 Jacob/wb 定, 但必须与误绿一致**。
- **违章09(seed2)**: 34 gt_green 帧全 had_cands, best_color=green **仅 12/34**, 判别器系统性选不中 → 漏绿29(全场最高)。**与 09 prior 偏框记录吻合([[prior-misframe-rootcause]] 05/06/09 IoU 低)**: prior 指偏 → 候选/crop 区域系统性错位 → 选不中真 gov 绿灯。**这是 prior 根因漏进来, 非判别器质量。**

## 2. neg_a 的真实画像(不是"净回退失败")
- **误绿轴大赢**: neg_a 误绿(扣05)=**0.88%** « base 2.19% « 上轮塌缩修复后的 3.56%([[governing-disc-collapse]])。硬负例挖矿把误绿砍到 <1%。
- **漏绿轴退**: worst-seed 91 vs 上轮 81 —— 硬负例让模型更保守(多弃权)→ 误绿↓换漏绿↑, 经典 precision/recall 权衡。
- **但漏绿退主要落在 05(口径)+09(prior 偏框)两个非判别器根因上**。扣掉 05、修好 09 prior, 漏绿大概率过关。**neg_a 方向有信号(印证 [[selection-precision-ranking-bottleneck]] "判别器/A消融有救"), 不是死路。**

## 3. 裁定
- **✅ 同意: 不接线, 留 B-only**。gate 按预设红线判 FAIL, wb 诚实执行, 操作上不接线是安全的 null-action, cc 无异议。neg_a 缓存独立(`*_A.pt`/`*_s1A.jsonl`)不改 B-only 定论, 对。
- **⚠️ 反对框定"neg_a 失败/放弃判别器"**: FAIL 是"05 漏绿口径不一致 + 09 prior 偏框"的合成, 非判别器质量定论; 且误绿轴大幅改善被这个框定埋没。
- **wb 诚实度记一功**: 主动发现"14分钟完成"可疑并查明是缓存复用、gate 红线没往下挪、预先承诺不过就如实报——正是要的纪律。

## 4. 下一步(建议, 交 Jacob/wb)
1. **统一 05 的漏绿口径**: 决定漏绿是否也扣05(与误绿一致)。若扣 → worst-seed 77≤80, 需再对 B-only 同口径比才能定是否净收益(cc 手上无 B-only 扣05漏绿, 需 wb 补)。

3. prior 修好 + 05 口径统一后**重跑 neg_a LOVO**, 再终判是否接线。neg_a 的误绿信号值得这次重评。
