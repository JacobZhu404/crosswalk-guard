# CC 复核裁定:L3 护栏全过 + 增益真实但温和(+9pp 固定w,非+12.5pp) + 治不了结构性召回洞

## 0. 裁定
- **护栏全过**:LOVO 排除本视频(eval:112 `if vv!=V`)、`select_gtfree` 默认 l3=None 行为不变(:126)、生产路径不读 GT、auto_ped 来自 GT 但 LOVO 已排除 → 无泄漏。**default-off,可安全留在树里不接线。**
- **增益真实但温和**:L1+L2 基线 62.5% → 加 L3 固定 w≈0.5 **71.9%(+9.4pp)**;w=1.0 的 75%(+12.5pp)是**小样本扫参噪声,不采信**。

## 2. 三个必须点破
1. **w=1.0"最优"= 噪声,禁 cherry-pick**:32 实例上 +12.5pp=净翻 4 个;各视频最优 w 乱跳(0.2/1.0/0.3/0.2/0.5)。诚实口径=固定 w≈0.5 的 +9.4pp;w 应嵌套 CV,不后验挑。(本会话反复的小样本扫参过拟合坑。)
2. **w=1.0 最优 = L1/L2 base 近乎无贡献**:纯 L3 反最好 → 几何+时序先验没拉力,是 smell,须查(别默认 L1/L2 有用)。
3. **结构性召回洞 L3 补不了**:05 车灯锁定=候选里无 ped 灯,L3 再准也没得选(det=1 选错);06/07/11 全没动。**L3 治"有 ped 也有车灯时挑对"(精度),治不了"根本没检出 ped 灯"(召回)。** 召回洞是检测问题(密集标注→ped 检测器那条路),L3 结构上补不了。vehicle 类仅 15 样本,ped-vs-车灯边界弱监督,加重此洞。

## 3. 处置 / 下一步
- **L3 留树、default-off、不接线**:增益温和且不治硬骨头,不值得现在动生产。
- **接线前先补**:①用嵌套 CV 定 w(别用 w=1.0);②查 L1/L2 为何无贡献;③直面召回洞——05/占比大的 11 不靠 L3,得靠检测(密集标注→检测器,或更大 YOLO/imgsz 提候选质量)。
- **扩样本**:vehicle=15 太薄 + 32 实例评测太小 → 增益置信度低;若继续走 L3,需更多 vehicle 标注 + 更多评测帧(否则数字不稳)。
- **红线**:未接线、未碰 enforce_transition_limit、default-off、护栏在。

## 4. 与上轮方向的关系
L3 是"选候选"路径,天花板=候选质量;它把 62.5%→~72% 是真进步,但**召回洞(05/遮挡/小灯)仍在**——这正是上轮"密集标注→ped 检测器"要解的。L3 与检测器不互斥:L3 提精度,检测器提召回。若目标是生产泛化,召回洞迟早要正面解。
