## Q1 详细：01 误绿根因（prior 位置偏移 → 环境绿）

### 数据事实
- **01 是红灯视频**（GT 全段 red，48-62.5s 为 occluded 遮挡段）
- **65 帧误绿**（pred=green 且 gt=red），分 4 个连续段：

| 段 | 时间(s) | 帧数 | g_px 均值 | g_px 最大 | r_px 均值 | conf 均值 |
|---|---|---|---|---|---|---|
| ① | 9.7–12.7 | 14 | 122 | 345 | 227 | 0.35 |
| ② | 19.6–23.1 | 16 | 81 | 360 | 727 | 0.33 |
| ③ | 46.9–50.5 | 16 | 164 | 531 | 145 | 0.43 |
| ④ | **56.1–60.4** | **19** | **2568** | **10913** | 550 | 0.54 |

- 01 的 prior = `[0.35, 0.35, 160]`（归一化中心 + 160px ROI）

### 抽帧视觉验证（/tmp/diag_light/v01_*）
- **t=10 全帧**：灰车停在斑马线上，**背景立杆信号灯明显红灯**（右上/中上部）。Prior ROI [0.35,0.35] 落在**车顶/挡风玻璃区域**，**不在信号灯上**。
- **t=10 ROI crop**：内容 = **车顶金属反光 + 背景树枝叶**。无信号灯。绿像素 150(0.6%) 来自树叶（春树 H∈40-100 落入 _classify 绿区间）。
- **t=21 ROI crop**：同上，车顶+树枝。
- **t=58 ROI crop（④ 暴涨段）**：车窗玻璃暗区（遮挡段），几乎无信号。g_px=2568 来自聚类头面积加总（非 ROI 直采），说明 prior 半径内有大型绿候选（可能是远处树木/绿化带被聚成信号头）。

### 根因判定
**Prior [0.35, 0.35] 位置不准确**——指向车辆上半部而非信号灯立杆。ROI 内的"绿"来自：
- **(a) 树枝叶**（春树饱和度足够过 sat_min=35，H 过绿区间）
- **(b) 车顶/玻璃反光**（低饱和但 V 高）
- **(c) ④ 段 g_px 暴涨**：遮挡段信号灯不可见，但 prior 半径内远处绿化带/树木被 _candidates 生成绿亮斑 → 聚类成"伪信号头" → 面积胜出 → 判 green

**这是 (a) 颜色误读(环境绿进 prior ROI) + (b) prior 位置偏差** 的组合。不属于"融合放大瞬态"（conf 本身就低 0.33-0.54，融合层也不确定但被迫二选一）。

### 佐证：同类视频也有 prior 偏的问题
- **06**: 81 帧误绿，prior=[0.65,0.45]（靠近画面下半部，可能是行人/绿化带区域）
- **02/03/11**: 各 36/75/28 帧分散误绿（部分也是 prior 边缘环境绿）

**关键发现**：

3. **但 pred 直到 43.1s 才翻 green** → 融合层延迟 **~0.9 秒**

### 抽帧视觉验证（/tmp/diag_light/v04_*）
- **t=42.9 全帧**：白色 SUV 在道路上，**立杆行人信号灯清晰显示绿灯**（绿色行走人形图标亮着）✅ **绿灯确实存在**
- **t=42.9 ROI crop**（prior=[0.58,0.15], 220px）：内容=**建筑立面窗户+前景树枝**（prior 指向左上角建筑区，也不在信号灯正上方）。绿像素 83(0.2%) 来自建筑/树的杂色。

### 根因判定
**逐帧检测器在 42.2s 后已观测到绿（g_px 持续非零、r_px 归零），但融合层 `_state_from_global` 的 `prior_flip_on=5` 要求连续 5 帧绿才翻转。由于：**
- (a) FrameDataset 采样间隔可能 >0.3s（非逐帧）
- (b) 42.2s 前 g_px 有回落（63/25 瞬态）打断了连续计数
- (c) 即使 42.4s 后 g_px 持续，也要攒够 5 个采样点才翻

→ **翻转迟到 ~0.9s，视频末尾只剩 1 帧 green → overlap 不足 → 漏检。**

**根因在融合（迟滞/翻转阈值），不在检测。** 修法方向 = 非对称短绿放行（检测到 r_px 归零 + g_px 持续时快速翻转），而非改检测器。

## Q4 详细：为何从不输出 unknown

### 代码追踪（`traffic_light.py`）

```
detect() → observe()/_select_lit() → obs ∈ {green/red/off/None}
         → global_recent.append(obs)
         → _state_from_global() → state
```

**先验模式分支**（line 762-787，所有有 prior 的视频走此路）：
```python
# line 767-787 精简:
seen = g + r                        # global_recent 里 green+red 计数
if seen == 0: return "unknown"      # ← 唯一回 unknown 的路径
gr, rr = g/seen, r/seen            # 否则二选一
# ... 迟滞/翻转逻辑 ...
return "green" or "red"            # ← 永远不回 unknown
```

**`_sample_prior_color()`（line 597-657）为何总返回颜色：**
```python
min_frac = 0.002   # line 650: 只要 0.2% 有色像素就返回颜色
g_mask = cv2.inRange(hsv_roi, [35,60,40], [95,255,255])   # 绿范围宽
r_mask = ...                                            # 红范围宽
g_n = countNonZero(g_mask); r_n = countNonZero(r_mask)
if g_frac >= 0.002 or r_frac >= 0.002:  # 几乎总是 True
    return "green" or "red"
# 只有极暗/纯黑 ROI（如纯夜空）才 return None
```

**为什么 0.002 太低**：160px × 160px = 25,600 px。0.002 = **51 px**。任何含树叶/反光/车漆的自然场景 ROI 都有 ≥51 px 的绿/红像素。→ `obs` 几乎永不为 None → `seen` 几乎永不为 0 → **几乎不输出 unknown**。

### 实测验证
- **GT-unknown 共 163 帧**（09 的两段 tentative）
- **预测分布**: green=152 (**93.3%**) / red=11 (**6.7%**) / **unknown=0 (0%)**
- **各视频 unknown_pred 总计**: 01:4, 02:4, 03:8, 04:2, 05:2, 06:3, 07:4, 08:2, 09:4, 10:3, 11:4 → 合计仅 **40 帧**（占 3308 帧的 1.2%，且多出现在视频首尾初始化阶段）

### 对 D1 安全网的影响
原设计意图：unknown + 遮挡 → 降级 review/不自动 confirmed → 防止误报。
当前状态：**安全网完全不工作** —— 93.3% 的 uncertain 帧被强行判 green → 直接触发假违章。
