## 1. 方法 (只读)
脚本 `scripts/diag_feature_separability.py`: 复用 `cli.run`(零循环复制), monkeypatch `observe` 抓取每帧生产 `obs` 及「决定绿的区域」的特征电池。6 视频 `light_priors.json` 均有 prior → 路径统一。仅统计生产判 `green` 的帧: 01 = 56 帧(假绿), 05/06/07/08/09 = 2051 帧(真绿)。

特征电池(从决定绿的区域: prior ROI / YOLO 框 / 全局最大绿连通域):
- 饱和度: `s_med/s_mean/s_p10/s_min`, `frac_s_lt120`, `frac_s_lt130`

## 4. 结论 — 外观特征全部不可分, 结构路线 #3 是唯一出路
1. **饱和度(#1)与紧凑度(#2)双双失败且方向反**: 01 假绿 `s_med` 139 > 真绿 86.75; `max_sol` 0.764 > 真绿 0.541。即 wb 预锁的 solidity 在真实数据上**指向错误**——真交通灯绿是低饱和(frac_s_lt120 0.83–1.0)、低 solidity(0.49–0.66)、且常很小(g_frac p10=0.001, max_area p10=24px); 假绿反而是块较饱和、较实、较亮的亮斑(树叶/反射/车漆)。cc「别预锁 solidity 再调阈值」一语成谶。
2. **无任何单外观特征可在留 margin 下分开且过 06 石**: `g_frac`/`max_area`/`v_med`/`dist_c` 即便方向对, 也与真绿尾部严重重叠(p10=0.001 / 24px / p90=174 / p90=0.498)——任何阈值都会屠 06 的低饱和小真灯。这正是 ped_signal.pt 屠真绿的重演风险, cc 禁一切外观变体正是为此。
3. **唯一稳定判别是上下文=遮挡**: 01 全程 `occluded`(事件 GT 标 occluded), 真绿视频(05/06/07/08/09)非 occluded。外观无法分, 但「是否遮挡」能干净分开——这恰是 cc 指定的结构路线 #3。
