## 1. 结论先行

1. **09 的 [85-106] 类持续假绿实际规模为 34s**, 非 21s。位置在 `[72.7, 106.1]`, 落在 GT 标注的 `unknown/tentative` 区间 `[72,999]` 内(视频总长 106.4s)。
2. **根因不是 `prior_roi_expand_factor=2.0`**(160px→320px 扩展)。扩展仅在 3/34 帧触发; 其余 31 帧来自 **紧 160px ROI 本身** 采到车辆绿。故扩展是次要/偶发因素, 不是治本杠杆。
3. **主导根因 = 生产 prior ROI 位置 + 宽松颜色投票**: 09 当前 prior `(0.2,0.35)` 在灯灭尾段正好框住一辆黄绿出租车 / 车身绿; 早先 prior-重定位调查以为的"真灯位 `(0.50,0.10)`" 经抽检实为**树叶/树冠陷阱**, 不是行人灯。
4. **根本问题是 `traffic_light._sample_roi` 的 HSV 颜色投票缺乏灯形/灯境判别**: `sat_min=60`, `min_frac=0.2%`, `g_frac>r_frac*1.3` 会把任何绿色饱和 blob(车身、树叶、反光)判成 green。这就是判别器重训线的价值: 用形状/上下文把"信号灯"与"环境绿"分开。

## 2. 方法

### 2.1 复刻生产 prior 直采路径

在独立脚本 `scripts/mine_false_green.py` 中, 用 cv2/numpy **逐比特复刻** `traffic_light.py`:

```python
_sample_prior_color():
  1. 在 prior(cx,cy) 取边长 160px ROI -> _sample_roi()
  2. 若 tight ROI 返回 None(暗) -> 扩展 160*2.0=320px 再采

_sample_roi():
  - HSV 范围: 绿 [35,60,40]~[95,255,255], 红 [0,60,40]~[12,...] ∪ [158,60,40]~[180,...]
  - min_frac=0.002
  - g_frac > r_frac*1.3 => green
```

注意: `_sample_roi` 的 `sat_min=60` 与生产候选路径 `self.sat_min=130` 不一致(生产管线已知 gap); prior 直采自身就用更低阈值, 这正是它能"采到"车辆绿/树叶绿的原因。

### 2.2 GT-锚定的假绿分类

`datasets/gt/light_states.csv` 只覆盖关键时段, 其余为未标注。为不夸大规模, 只把 **GT 显式覆盖且状态非 green** 的 prior-green 帧计入统计:

| 类别 | GT 状态 | 含义 |
|---|---|---|
| **definitive** | `red` | 硬证据: GT 红, prior 却绿, 当前即可能记分 FP |
| **suspected** | `unknown` / `occluded` / `off` / `tentative` | 灯态未明确或已灭; prior 绿 = 隐患(09 [72-106] 属于此类) |
| **unannotated** | `None`(CSV 无覆盖) | **不计入假绿**。例如 05 `[30,65.7]` 全部绿帧落在此类; 05 是 violation 视频, 这些更可能是未标注的**真实绿灯**而非假绿。 |

### 2.3 采样率

以 1fps 采样(每视频约 100 帧), 足以刻画秒级持续段, 计算代价极小。如训练集需更高密度, 方案文档中再提。

### 2.4 视觉抽检

对 09 在 `t=20,40,80,90,95,100` 截取:
- `cur`: 当前生产 prior `(0.2,0.35)` 的 160px 与 320px ROI;
- `true`: 早先 prior-重定位调查认为的 "真灯位 `(0.50,0.10)`" 的 ROI。

用于区分 "车辆绿 / 树叶绿 / 真灯" 三种视觉来源。

### 3.2 关键解读

- **09 的 `[72.7-106.1]` = 34s 持续 prior-green**, 全部落在 GT `unknown` 区间 `[72,999]`。这正是 brief 所称 "[85-106] ~21s 持续假绿" 的完整形态(21s 只是其子集或近似值)。
- **扩展不是主因**: 09 这 34s 中 31 帧来自 **紧 160px**, 仅 3 帧来自扩展 320px。
- **definitive 总量 55.58s** 中, 06 占 13.18s(但 06 GT 为 `[0-29] green, [29-∞) red`; 这些 red 区间绿读可能是车辆/反光, 对 06 当前输出无影响, 属潜在风险), 01/02 各约 10s(真负/红相位视频, 也不直接产生记分 FP)。
- **05 没有可确证的假绿**: 其 `[30,65.7]` 全部 36 帧落在 GT 未标注区, 更可能是未标注的真实绿灯(05 是 violation 视频)。**05 的脏袋问题是 b2 tracker 合并线, 不是 prior 假绿线。**

### 3.3 绿像素质心偏移(区分"集中灯" vs "弥散环境绿")

对每个 false-green run 计算绿像素二阶矩质心相对 ROI 中心的归一化偏移(0 为中心, 0.5 为边缘)。结果:

- 09 `[72.7-106.1]` 平均偏移约 **0.10-0.20** — 看起来相对集中, 但这与"车辆绿"不矛盾: 出租车车身绿占据了 ROI 中心区域。
- 01/02/04/07 等零散 definitive 帧偏移 **0.30-0.50** — 多为边缘树叶/反光/远车绿, 明显是环境绿。

## 4. 根因抽检: 视觉证据

### 4.1 09 当前 prior `(0.2,0.35)` 的 ROI

| 时间 | 状态 | 160px ROI 内容 | 320px ROI 内容 |
|---|---|---|---|
| t=20 | GT green | 树木/车辆混合, 未见清晰行人灯 | 左侧出现信号灯杆, 但 ROI 中心仍是街道/车 |
| t=40 | GT green | 车辆/行人, 无清晰灯 | 信号灯杆更完整, 但 ROI 中心偏下偏右 |
| **t=95** | GT unknown(目标段) | **黄绿出租车车身占据 ROI 中心** → 假绿来源 | 杆+出租车同框, 扩展区域包含更多车身绿 |

### 4.2 09 "真灯位 `(0.50,0.10)`" 的 ROI — 实为树叶陷阱

| 时间 | 160px ROI 内容 |
|---|---|
| t=20 | 树冠/树叶 |
| t=40 | 树冠/树叶 |
| t=80 | 树冠/树叶 |
| t=95 | 树冠/树叶 |

**结论**: 早先 prior-重定位调查中 "(0.50,0.10) 是 09 真行人灯" 的发现**不成立**。该坐标在 GT green 段与 unknown 段都只看到树叶; 它之所以在 grid scan 中表现为"绿持续时间长", 是因为树冠在 HSV 下稳定地绿, 恰好被宽松颜色投票捕获。这是与当前 prior `(0.2,0.35)` 相似的另一类**环境绿陷阱**。

### 4.3 根因定级

| 候选根因 | 证据 | 占比/强度 | 结论 |
|---|---|---|---|
| **ROI 扩展到 320px** | 仅 9 帧(def+susp) 触发扩展 | ~9/93 ≈ 10% | 次要, 不是 [85-106] 持续段主因 |
| **prior 偏框 (09 prior 太低/太偏)** | 当前 prior 框到出租车车身; 扩展 320px 才把信号灯杆纳入 | 中-强 | 重要诱因, 但红线禁止改 prior 坐标 |
| **宽松 HSV 颜色投票无形状/上下文判别** | 车辆绿、树叶绿都被判 green; 真灯位 `(0.50,0.10)` 实为树叶 | **最强** | 根本问题; 需要通过判别器重训解决 |

## 5. 对重训方案的启示

1. **不能靠调 prior 坐标**: 红线禁止; 且即便把 prior 移到 (0.50,0.10) 也只是从"车辆绿陷阱"换到"树叶绿陷阱"。
2. **不能简单收紧颜色阈值**: 当前 prior 直采正是为了"行人灯小/暗时仍能被检测到"; 收紧 `sat_min` 会伤害 recall(关 02/03 等暗绿)。
3. **需要判别器理解"灯"**: 在 160px prior ROI 内, 区分行人信号灯(圆形/人形图标、在杆上、有灯罩结构)与车辆/树叶/反光。这正是 Phase B 重训的核心目标。
4. **数据标注来源**: 用 GT `light_states.csv` 给 prior ROI 帧打时间标签, 结合本次 mining 挖出的 hard negative(车辆绿、树叶绿), 组成监督数据。详见配套方案文档 `2026-08-19-wb-discriminator-retrain-dataset-plan.md`。
