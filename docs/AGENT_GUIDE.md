## 0. 一分钟认识这个项目

- **做什么**：输入手机拍的路口视频，检测「行人绿灯时车辆仍静止压在斑马线上」的违章，识别车牌，输出标注视频 + 违章事件表 + 证据截图。
- **违章的权威定义**（E12 反转后，唯一正确语义）：
  **违章 = 行人绿灯/闪烁清空相位　∧　车辆静止　∧　车辆压在斑马线上　且持续足够时长。**
  - 🔴 红灯 = 车可通行，**不算违章**。
  - ❓ 没拍到灯 = 默认不判违章；仅当斑马线疑似被遮挡时降为「待复核」。
  - 权威规格见 `docs/plans/2026-07-12-design-requirements-v2.md`，**改任何判定逻辑前先读它**。
- **技术栈**：纯 CV + 轻量模型（YOLOv8n 车辆 / HSV 颜色法红绿灯 / HyperLPR3 车牌），**不用大模型（VLM）**，CPU 可跑，结果确定性可复现。

## 2. 🚫 红线 / 死路（违反 = 重踩已验证的坑）

> 这些不是「建议」，是**已经用实验否决掉的路**。每条都附「为什么」，让你能判断新情况是否真的不同。

### 2.1 不要碰「0 误罚」这条底线
- **误罚（给一辆 GT 已知非违章的车开罚单）= 一票否决。** 任何改动必须保持全 11 视频误罚=0。
- 守门的是 `src/redlight/app/cli.py` 里车牌回填的**三重约束**（静止占比≥0.6 / 全局帧数≥5 / 空间聚集 span≤0.25×帧宽）。尤其**空间聚集约束**（约 cli.py:283-294）是挡「违章05 把黑车牌 京N541E6 安到白车上」的关键闸门。
- 有回归测试 + 变异测试守护（`tests/unit/test_cli_plate.py`）。**改车牌逻辑前先跑这些测试**，拆掉空间约束会立刻复现误罚。

### 2.2 不要试图用「挪红绿灯位置先验」修假绿
- `configs/light_priors.json` 里多数视频的先验框是偏的（05/06/09 与真灯 IoU=0）。这是历史遗留。
- **已验证**：把 09 的先验重定位到真灯位，假绿不但没修好，反而从 0.856 恶化到 0.969（见 `docs/history/branch-archive/2026-08-18-wb-09prior-relocate-investigation.md` 和 `docs/history/plans/2026-08-04-wb-plan-09-06-prior-relocation.md`）。
- **根因不是先验位置**，是 HSV 取色区域（ROI）太大 + 面积投票无形状约束 → 把环境里的绿（出租车/植被/反光）数成了绿灯。挪位置治不了。

### 2.3 不要直接接现有的 `ped_signal.pt` 判别器去「治本」
- 曾有「用学习式判别器替代颜色法」的方向。现有权重 `models/ped_signal.pt` **过拟合、会屠真绿**，不可直接接线。
- 判别器重训这条线（代号 discriminator / governing_disc）**已被项目所有者（Jacob）拍板 HOLD**。原因：全量口径下质量 FAIL（见 `docs/history/branch-archive/2026-08-19-wb-discriminator-retrain-*.md`、`docs/history/handoff/*governing-disc*`）。
- 若要重启，**治本方向是「弥散绿空间/形状判别」**（给颜色投票加形状约束），不是挪先验、不是重训现有权重。而且这是战略决策，**要先问项目所有者**。

### 2.4 「违章04 漏检」是结构性难例，不要指望小改能救
- 04 的真绿窗只有约 1.2s，且落在视频结尾；而负例 01 的**假绿**最长有 3.10s。04 真绿比 01 假绿还短。
- 因此**没有任何时序门控阈值能同时救 04 又不放进 01**（已三次独立验证）。想救 04 只能靠 §2.3 的判别器线（HOLD 中）。
- 现有 #3 时序门控阈值 `min_persistent_green_run_s=6.0`（`configs/config.yaml`）是精心调过的，落在「01假绿3.10s」和「真绿最短10.27s@违章11」之间，**别乱动**。

### 2.5 评测口径的陷阱
- 评测**必须跑负例**（违章01/10，GT 无违章），否则看不到误报。曾有「不跑负例 + 把真违章碎片记成 FP」的度量 bug，导致指标虚高。
- 不要用 `select_gtfree` 这类非生产路径的指标下结论——**生产路径是 `observe()`**，离线选灯评测可能在量「幻影」。
- 「按车辆算」的车级评测已落地（`match_cars`/`aggregate_car_level`，`eval_violations.py` 会打印），但注意：**真正「拆开同一窗里的多辆车分别计分」还需要 tracking-GT 标注**（目前没有），车级评测现在只是让「漏掉第二辆车」变得可见，不等于能拆。

## 3. 工程纪律（沿用，别破坏）

- **先诊断，后改码**：定位问题用只读诊断脚本（见 `scripts/legacy/` 里几十个 `diag_*` 的先例），量化根因，再动生产码。
- **改动必须全 11 视频真跑验证**，指标不回退、误罚=0，再提交。别凭感觉调参。
- **数字矛盾时找 bug，别折中**：两个测量打架，一定有一个有 bug，复现定位它，不要取平均或选边。
- **测试套件**：`python -m pytest tests/`（当前 375 passed, 1 xfailed）。那个 xfail 是判别器线 HOLD 的占位，别去「修」它。
- `pyproject.toml` 里 `--import-mode=importlib` 别删（修同名测试文件撞车用的）。
