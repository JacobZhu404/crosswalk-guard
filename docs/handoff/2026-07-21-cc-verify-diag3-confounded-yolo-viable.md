# CC 复核裁定:Diag3 命中率**指标被相机运动污染**,YOLO 并非"框不住"——修正后 57–64% 命中,方向仍是逐帧定位(非固定 prior)

> 出自 cc(arbiter)。wb 的 Diag3 结论"YOLO 框不住行人灯(命中 0–4%)→ 重挖走固定 prior 重定位"与我上一轮"手持相机运动使固定 prior 作废"直接冲突。我独立复核,定位到指标 bug。

## 0. 裁定
- **wb 的命中率指标被污染,不成立**:`diag_yolo_vs_gt.py` 的 `eval_video`(:82/133)把**每一帧**的 YOLO 框都去比**同一个静态 canonical 框**(由 `derived_per_video.true_center` 推,全视频一个),`hit_rate_all=n_hit/n_frames`。但相机在动、灯逐帧位移 → 多数帧静态参照本就错位,YOLO 即便正确框住(移动后的)灯也判 miss。**0–4% 是运动假象,不是 YOLO 无能。**
- **公平测试(只在标注帧比该帧 GT 框)推翻结论**:YOLO 中心落在行人灯 **64%(18/28)**、IoU≥0.3 **57%(16/28)**、IoU≥0.5 36%(10/28)。**YOLO 多数时候能找到行人灯,逐帧、跟得住运动。**
- **wb 的"走固定 prior"建议双重不成立**:①固定 prior 跟不住相机运动(上轮 finding);②YOLO 并非框不住(本裁定)。**方向仍是逐帧定位,不是回固定 prior。**
- 但也**不是裸 YOLO-crop 一锤定音**:IoU≥0.5 仅 36%,03/05/08 弱。需正经设计(逐帧检测 + 跟踪/时序 + GT 校验),非天真裁 YOLO 框。

## 1. 证据
公平测试:对 GT 里每个标注帧 fi,跑 YOLO(cls9,conf0.05)于 `frame_{fi}`,比**该帧** `true_box_norm`:

| video | 帧 | IoU≥0.3 | IoU≥0.5 | 中心近<0.06 |
|---|---|---|---|---|
| 01 | 2 | 2 | 2 | 2 |
| 02 | 3 | 2 | 0 | 2 |
| 03 | 3 | 0 | 0 | 0 |
| 04 | 3 | 2 | 2 | 3 |

| **总** | **28** | **16 (57%)** | **10 (36%)** | **18 (64%)** |

对比 wb 静态框指标:02=0.2% / 05=0% / 06=0.5% / 09=4.4%。差距全在"静态框 vs 动相机"。IoU 偏低部分因 YOLO 框(整灯头)比 GT 框(单灯/紧框)大,故"中心近 64%"比 IoU 更能反映"找没找到"。

## 2. 为什么两个 finding 一起看,答案是"逐帧检测"
- 固定单点 prior:跟不住运动(06 灯 t20@0.61→t40@0.40)→ 死路。
- YOLO 逐帧:64% 中心命中 → 跟得住运动、有料,但不完美(36% IoU≥0.5,03/05/08 弱)。
- ∴ 架构应是**逐帧检测为主**:YOLO 作逐帧候选 + 跟踪/时序补空 + Jacob 逐帧 GT 作校验/微调,而非静态 prior,也非裸 YOLO 裁框。

## 3. 要求 wb 重做 Diag3(指标修正)
1. **命中率必须按帧比该帧 GT**(用 `annotations[].true_box_norm` per-fi,不用 canonical 静态框)。canonical 框在动相机下无意义。
2. **中心距 + IoU 双指标**:IoU 受框尺寸差压低,中心距更能判"找没找到";两者都报。
3. **人眼确认 ped-vs-vehicle**:近中心的 YOLO 框到底是行人灯还是恰好在附近的车灯/杆灯?抽几帧叠框看,别让"近中心"混入车灯假命中。
4. **弱视频单列**(03/05/08):是 YOLO 真漏还是这些视频灯太小/被遮;决定是否需更大 YOLO 或 ped 专用检测器。
