## 0. 一句话

罚单的计数单位是**"每次过街窗"**还是**"每辆违章车"**?这一个词决定脏袋过合并**能不能真拆**,以及要不要你额外补标注。

## 1. 决策点(唯一变量)

评测契约 `match_violation_events`(violation_eval.py:152)现在是**贪心 1:1**:events.csv 每个正例视频恰好 1 个 `is_violation=1` 窗(02/03/04/05/06/07/08/09/11 = 9 窗)。一个窗只认 1 个 pred,其余 pred 全记 raw FP → 主 `precision`(:192)。

∴ **同窗内拆出第二辆车(哪怕它是真违章)= +1 FP = 主 P 1.0→0.5**(cc 端到端仿真坐实,非观点)。这不是 bug,是"窗级"语义的直接后果。

## 2. 两个选项 × 下游代价

| 维度 | **A. 窗级("每过街窗 1 票",= 现状)** | **B. 车级("每违章车 1 票")** |
|---|---|---|
| 罚单语义 | 一次红灯过街 = 最多 1 张罚单 | 一个窗里 N 辆违章车 = N 张罚单 |
| 主 precision 指标 | 维持现 `precision`(:192),P=1.000 | 改采 `p_only_true_fp`(:244)为准,需重写契约 |
| 脏袋过合并能否真拆(α) | **永久不能**。拆真违章车也破 P → 只能 φ 窗收窄 + 车牌侧治理(= D1 封顶) | **能**。同窗拆出真违章车对 `p_only_true_fp` 零影响 → α 合法解合并 |
| 需要你额外做的事 | **无**。D1 出方案→gate→落地即可 | **需你补 tracking-GT null 框**:02/07/09 各 2–3 帧 anchor,判 97 个盲盒 member 是真违章车还是搭车(否则拆不动、也判不了对错) |
| 工作量级 | 小(D1 一条线,零新标注) | 大(评测契约级改动 + 新标注 + 独立立项 + 全 11 回归) |
| 现实收益 | 02 错罚已被 P2 止血 + D1 断根因;当前输出已 0 误罚 | 仅在"一个窗真有多辆各自违章的车、且都该独立开单"时才多出票——**本数据集是否存在这种窗?未证** |
| 风险 | 低(D1 by-construction 不破 P) | 高(去合并重新打开"搭车 member 暴露成记分 FP"风险;97 盲盒判错 = 错罚真人) |

## 3. cc 的判断(建议,非替你拍)

**倾向 A(窗级)**,理由三条:
1. **收益侧空**:D1 已能断 02 错罚根因,当前车牌输出已 0 误罚。B 的额外产出("一个窗多辆车各自开单")在本数据集**未被证明存在**——为一个未观测到的场景付评测契约改动 + 标注成本,划不来。
2. **成本侧重**:B 要你亲手补 02/07/09 的 tracking-GT null 框(判 97 盲盒),这是唯一能解锁 α 的钥匙,但也是你时间的真消耗。
3. **风险侧差**:B 的去合并会重新打开 cc plan-gate 头号 FP 风险(搭车 member 变独立记分 confirmed),而 A/D1 从设计上规避了它。

**唯一该选 B 的情形**:执法产品定义就是"一辆车一张单",且你确认真实路口存在"同一红灯窗多辆车分别违章各需独立取证"的高频场景,愿为此补标注。
