## 0. 为什么还值得测这一轮(信号立足点)
四路全死是因为在**单帧外观/单帧结构信号**上,01 的假绿(大实心绿车面,S 152)落在真绿分布正中。但**时序**是唯一未测的正交轴,且有立足点:
- cc 复核 `diag_01fp.json` 实测:01 的 raw observe 绿在 **49.3→51.59s** 和 **53.611→55.901s** 各有 ~2.3s **红缝隙**,而 `light_segments` 是单段 green [48.36-61.29] —— **时序融合把闪烁桥接成了持续绿**。物理上:过路车/反光是**瞬态**,真信号绿是**持续**。这条轴针对的正是"瞬态 vs 持续",非外观阈值。

## 1. 两条候选时序轴(不预锁,横测取胜者)
**A. 绿持续性/闪烁(raw observe 层,融合前)**:在每个候选绿段内测 raw observe 绿的 run-length 分布 + 红打断频次/最长红缝隙。假设 01 假绿=短 run + 多红缝隙;真绿=长 run 少打断。**必须在融合前的 raw `observe()` 输出上测**(融合后 01 已被桥接成持续,信号被抹掉)。
**B. 绿斑位置稳定性**:测绿斑质心 (px,py) 随时间的方差/最大漂移。假设真灯=定点(低方差);过路车绿=漂移(高方差)。cc 实测 01 的 g_cx 在 0.256→0.553→0.30→0.38 漂移。**注意扣手持机位整体漂移**(用相对 prior 或帧间差分,别把全局抖动记成灯漂移)。

## 3. ⚠️ 三个必答的证伪点(防第五次栽坑)
1. **真绿是否也闪烁**:06/09 真绿段若因行人往返/短暂遮挡也有红缝隙 → 轴 A 死。必须量真绿的红缝隙分布,不能只量 01。
