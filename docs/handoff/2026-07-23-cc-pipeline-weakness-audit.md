# CC 弱点审计:整条灯态识别流程的根性弱点 + 是否从头重设

> 出自 cc(arbiter),应 Jacob "搁置推进、先查全流程弱点、必要时从头商议标注/识别/训练" 之请。
> 诚实自审,含对 cc 自己此前建议的批判。

## 0. 一句话
**我们一直在给一个"从没被建出来的地基"打补丁——那个地基是"行人信号灯检测器"。** 几乎每个弱点都回溯到"没有任何组件是为'检测行人灯'这个目标物设计的"。

## 1. 逐关节弱点
| 关节 | 现状 | 弱点 |
|---|---|---|
| **候选生成** YOLO(COCO cls9)∪HSV亮斑 | YOLO 找车用红绿灯、非行人灯(~64%中心命中靠巧合,漏小灯05/08、漏遮挡03);HSV 对任意绿/红发火(=误绿根源) | **地基弱**:候选集既漏 ped 灯(召回洞)又混干扰(车灯/植被)。目标物根本没有专用检测器。 |
| **选灯** L1几何+L2时序+L3学习 | L3 +9pp(温和),L1/L2 近乎无贡献(w=1.0最优),vehicle 类仅15样本 | 只在"ped候选存在时"有意义,被候选质量封顶;选灯≠检测。 |
| **状态分类** walk/stand/off tiny CNN | 未在干净crop上重评(闭环没闭) | 完全依赖拿到对的crop(承上);暗绿等硬光照另是问题。 |
| **真值/标注** location_gt(33帧框)+ l3(203簇) | 稀疏、曾被循环使用(Diag2) | 无密集逐帧 box+state → 训不了检测器、做不了稳评测。 |
| **评测** | 曾循环(prior选来配GT、又在prior采样比GT);现仅32选灯实例 | **元弱点:我们一直在噪声/循环的数字上做架构决策**(w=1.0噪声、prior循环、静态框污染都被我逐个抓过)。32实例撑不起任何自信结论。 |

## 2. 三个根性弱点(彼此独立,却指向同一投资)
1. **没有行人灯检测器(地基)**:固定prior跟不住相机运动;YOLO是车灯检测器;HSV是误绿源;L1/L2/L3只是在烂候选里挑。上层全部继承候选天花板(~72%选灯 + 召回洞)。
2. **评测太弱、历史循环(元弱点)**:反复在32实例/循环指标上拍架构——这才是最危险的,因为我们**不知道自己站在哪**。没有一个够大、去循环、对**端目标(误绿率/违章F1)**的稳评测。
3. **GT 稀疏且曾循环**:两份 GT 都是补丁式,不足以训检测器或支撑稳评测。

## 3. 关键洞察:三个根性弱点由同一笔投资一次性解决
**密集逐帧 box+state 标注** 同时:
- (a) 让我们能训一个**行人灯专用检测器**(修地基#1)——它学 ped 灯外形,直接逐帧定位、不对车灯发火,选灯L1/L2/L3 基本消失;
- (b) 提供一个**够大、去循环的评测集**(修元弱点#2)——终于能对误绿/违章F1 做可信度量;
- (c) 提供**干净训练crop**(喂状态分类器)。
> 所以"密集标注"不是众多选项之一,而是同时拆掉三个最深弱点的那一笔。

## 4. 诚实的另一面(批判我自己的"上检测器"倾向)
- **11 视频对检测器太小**:行人灯形态差异大(有无倒计时/竖式横式/图标不同),11 段可能覆盖不全 → **对全新路口/手机的泛化未证**(但现方案有同样泛化风险)。
- **成本真实**:密集框 ~数百–1000 个。
- **召回洞其实"安全"**:检不出ped灯的帧=不出候选=**不产生误绿**(只漏检)。而原始病是**误绿(精度)**。→ **也许 L3精度 + 干净crop 已经能把误绿压到可接受,检测器属过度工程。** 这个我们**从没量过**。
- **状态硬光照(暗绿)**:再好的检测器也不自动解决暗绿判色,那是分类器/分辨率问题。

## 5. 决策岔路(需 Jacob 拍)
- **A 打补丁前行**:闭环一次,用当前最好定位+干净crop 量误绿。**便宜**。若误绿可接受→检测器不必要,收工。
- **B 从头重设**:密集 box+state 标注 → 训**行人灯检测器(+状态头)** + 建真评测。**贵但拆三根性弱点**。
- **决胜的那一个未测量**:A 的误绿数字。**它便宜且直接决定要不要 B。**

## 6. cc 的推荐(带倾向,非拍板)
1. **先做一件事定标尺**:一次性闭环量**误绿率**(A 的核心产出)——这是唯一能把"够不够好"从猜变成知的数字。**在这个数字出来前,不投 B 的大标注。**
2. **并行 30 分钟侦察**:有没有**公开行人灯数据集**可 bootstrap 检测器(降标注量 + 补泛化)?有则 B 的成本/风险大降,天平偏 B。
3. **无论 A/B,评测地基都得补**:32 实例撑不起决策——这是元弱点,迟早要更多标注帧做稳评测。既然要标,就往"能同时喂检测器"的密集 box+state 上标(一笔两用)。
4. **我的倾向**:鉴于"每次定位补丁都撞天花板 + 评测反复太弱/循环",**元弱点(评测太弱)本身就够格要求加大标注**;而该标注天然能喂检测器。所以我偏 **B,但先用 A 的误绿数字 + 公开数据侦察把风险/必要性钉死再全面铺开**。

## 7. 不做什么(纪律)
- **暂不发**"闭环重挖"brief 给 wb(Jacob 已搁置推进)——先定 A/B 岔路。
- 不在 32 实例上继续调 L3/选灯参数(噪声)。
