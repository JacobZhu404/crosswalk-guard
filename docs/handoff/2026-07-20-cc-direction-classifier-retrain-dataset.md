# CC → wb 方向:灯态判别器重训数据集(分阶段立项)

> 出自 cc。承接 `docs/reports/2026-07-20-wb-diag-classifier-feasibility.md`(现有 `ped_signal.pt` 不可用:3 视频过拟合、零 impostor 负样本、屠 06/07 真绿 0.98–0.99、漏 25% 假绿 → 净回退违钢锭②)。**Jacob 拍板:建重训数据集。** 治本方向(学习式判别器)对,资产不够,重训补齐。

## 0. 判别器目标(锚定,别跑偏)
- 用途:在 `observe()` 产绿出口做**门控**——判"这次绿读数来自**真行人信号**还是**impostor(背心/植物/反射/车反光等非信号绿)**"。
- 输入 = 采样器看的 prior ROI 框(与现训练 crop 同尺度);输出 = **真信号 vs impostor**(标签方案 wb 在计划里定,倾向三类:真绿/真红/impostor,既门控又validate颜色)。
- **成功标准 = 重训后重跑可行性诊断能过**(见 Phase B),不是"训练集 acc 高"。

## 1. 阶段划分(每阶段 cc review 后才进下一步)
- **Phase A**:构建数据集(挖矿 + Jacob 抽检 + 类平衡 + 按视频 split)。**先出构建计划给 cc review,再挖。**
- **Phase B**:重训 + **重跑 §可行性诊断**(拒背心/保 06-07 暗绿/过 04 试金石/未见视频泛化)。出再诊断报告给 cc。
- **Phase C(仅 B 过)**:接进 `observe()` + 端到端 eval 无回退。B 不过则回炉或转回退门控,**绝不硬接**。

## 2. Phase A 数据集构建(先出计划,别直接挖)
**挖矿源(半自动,降 Jacob 标注成本)**:
- **impostor 负样本**:诊断已定位的假绿 ROI —— 01(54 帧)/10(14 帧)+ 483 帧系统性误绿(红/未知判绿)的 prior ROI 框。这些就是背心/植物/反射的非信号绿。
- **真信号正样本**:confirmed 真信号帧的 ROI,**必须覆盖 06/07 暗绿 + 04 短绿**(被屠的那些)+ 各视频真红/真绿。
- **Jacob 的角色 = 抽检/确认**(不是从零标):挖出的 crop 按启发式自动打标(假绿帧→impostor、真信号帧→真信号),**用画廊(复用 `make_ped_signal_gallery.py`/`serve_gallery.py`)让 Jacob 抽检纠错**。自动标可能错(假绿帧里可能藏被误判的暗真绿;真绿帧 ROI 可能偏出信号)——抽检兜底。

**硬要求**:
- **按视频切 train/val(不是按帧!)**:必须留出若干视频做 val 测泛化——这是现有 pt 过拟合的直接教训。按帧切会泄漏、测不出泛化。
- **类平衡**:impostor 与真信号大致均衡(现有模型 walk 仅 20% 少数类→偏置屠绿,不能重蹈)。
- **全 11 视频覆盖**(现有仅 02/03/04)。
- 数据 manifest:逐类逐视频计数 + train/val split 明示。

## 3. Phase B 重训 + 再诊断(gate)
