# CC 发现(改方向):手持相机运动 → 固定 per-video prior 根本跟不住灯;重定心治标不治本,转逐帧定位

> 出自 cc(arbiter)。起于我对候选 `light_priors.rebuilt.json` 做的**非循环硬验证**(新 prior 能否让 --no-yolo 抓回 06 已知红段)。验证**失败并反证**,深挖出比"prior 设错"更根本的病。

## 0. 结论抬头
- **候选重定心方案(我建的 `light_priors.rebuilt.json`)被自己的验证证伪**:用新中心跑 06 `--no-yolo` 仍判全绿、漏真红段;09 反而丢了红段。
- **根因 = 手持相机运动**:06 的行人灯 t20s 在 (0.61,0.24)、t40s(红相)移到 ~(0.40,0.20),固定框落到**树上**(实测该框红相 red=0.00%/green=40-58%=树叶)。**单个固定 per-video prior 无法跟住移动的灯。**
- **方向修正**:固定 prior(含重定心)对手持视频是死路;**必须逐帧定位**。战略叉压向 **YOLO-crop**,wb 的"YOLO 框 vs 硬 GT 命中率"从选项升级为**关键路径**。候选 priors **作废**(最多静态段 fallback)。

## 1. 证据(06,直接看像素)
新 prior 中心 (0.61,0.24)、roi 160,在 06 时间线采样:
| 时刻 | GT 相 | 框内 green% | 框内 red% | 框内实际是 |
|---|---|---|---|---|
| 15s | 绿 | 30.3% | 0.16% | 灯在框内(绿)+ 树 |
| 20s | 绿 | 30.8% | 0.02% | 同上 |
| 40s | **红** | 40.5% | **0.00%** | **相机已移,框落在树上;真红灯(带倒计时36)在框左外 ~(0.40,0.20)** |
| 44s | 红 | 58.1% | 0.00% | 同上,更多树 |

看全帧叠框图确认:t20 灯在框内(绿行人),t40 场景整体左移、真红灯在框左侧、框套树。HSV 没坏(红灯不在框里所以 0% 红),**是框跟丢了灯**。

## 2. 这把之前所有现象串起来
- **8/11"偏框"**:固定点只在标定帧对,相机一动即错;Jacob 画的框也只对他标注的那一帧。
- **YOLO 兜住生产(Diag1)**:YOLO 逐帧重检、跟得住运动;固定 prior 跟不住 → 这才是 YOLO 救场的真机制。
- **候选重定心验证失败**:新中心对标注帧、错在其余帧。
- `prior_roi_px=160` 注释"吸收手持漂移":本例漂移 ~400px ≫ 160 框,该缓解远不够。

## 3. 方向修正
1. **弃用固定 prior 作主路径**:`light_priors.rebuilt.json` 与 `light_priors.json` 的 per-video 单点都跟不住运动;不作重挖依据。保留仅作静态段/YOLO 失效时 fallback。
2. **逐帧定位为主**:重挖 crop 必须来自**逐帧检测框**(YOLO 或轻量 tracker),天然跟随运动。
3. **wb 的 YOLO-vs-GT 命中率验证 = 关键路径**:若 YOLO 逐帧稳定框住**行人**信号灯 → 重挖走 YOLO-crop,固定 prior 整体弃用;若 YOLO 只框车灯/漏行人灯 → 需另找逐帧检测器(不是回固定 prior)。
4. **Jacob 位置 GT 的新用途**:不作固定 prior,而作**逐帧检测的校验真值**(YOLO 在某帧的框 vs Jacob 在该帧的框做 IoU)。注意 GT 框也是 per-frame 的,不能跨帧当静态位置用。

## 4. 对既有产物的处置
- `configs/light_priors.rebuilt.json`:标注为**作废/存疑**(本 finding),不 swap 进生产,不作重挖依据。
- `light_location_gt.json`:保留,改作逐帧校验真值。
- Step2 filter / classifier_retrain 数据:维持停用(建立在跟丢的固定 prior 上)。

## 5. 红线(不变)
先计划后动、不擅自重挖、生产 light_priors.json 不动(候选也不 swap)、gate 不过不接线、scoped git、署名、trunk main。
