# 信号类型诊断报告：02/03/04 行人信号识别

> 生成时间: 2026-07-12 14:08
> 范围: 仅行人灯识别（违章判定/遮挡推理/机动车信号推理均不在本期）
> 方法: shot_signal_type.py 每4s抽帧 + 肉眼确认锚点位置对应的物理信号

## 1. 核心发现

### 三个视频共同问题：检测器 ANCHOR 在多个信号灯之间横跳

| 视频 | ANCHOR 跳跃次数 | 不同位置数 | 是否稳定锁住一个灯 | 行人灯态正确率(估) |
|------|---------------|-----------|-------------------|------------------|
| **07** ✅ | 0 | 1 | t=1 锁定全程不动 | **100%** (0-42绿 / 43-44红) |
| **02** ❌ | ≥3 | 4+ | 否，在 0.56→0.19→0.42→0.86 之间跳 | ~50% (碰巧相位对) |
| **03** ❌ | ≥2 | 3 | 否，在 0.46→0.58→0.85 之间跳 | ~20% (全程读红) |
| **04** ❌ | ≥2 | 3 | 否，在 0.49→0.45→0.90 之间跳 | ~80% (大部分红对上) |

**07 的"t=1 锁死 + EMA 稳定"策略在多灯场景完全失效**。根因：画面里存在多个持久信号候选时，`_select_lit` 的 max_total 排序键会随时间切换到不同信号 → 锚点跟着重定位。

## 3. 根因分析

### 为什么 07 稳定而 02/03/04 不稳定？

| 因素 | 07 | 02 | 03 | 04 |
|------|----|----|----|----|
| 画面中信号灯数量 | 1 主导 | **≥4** | **≥3** | **≥3** |
| 行人信号 vs 其他信号的亮度对比 | 行人灯最亮 | 多个信号轮流最亮 | 右侧信号持续最亮 | 中间信号最亮 |
| 锚点是否首次就命中行人灯 | ✅ t=1 就锁对 | ⚠️ 先锁了机动车灯 | ❌ 从未稳定锁行人灯 | ⚠️ 基本对但末端跳 |
| reanchor 触发次数 | 0 | **≥3** | **≥2** | **≥1** |

**核心 bug**：当前 `_select_lit` 选头逻辑 = `max(max_total, lamp_score)` 排序。在多灯场景下：
1. 机动车红灯亮时 → 机动车信号 total 最大 → 锁机动车信号（读 red）
2. 行人绿灯亮时 → 行人信号 total 变大 → 可能切换到行人信号（读 green）
3. 但如果某个非行人信号因反光/反射一直保持高 total → **永远锁不到行人信号**（03 的典型案例）
4. 一旦当前锁的信号暂时变暗（遮挡/相位切换）→ 触发 reanchor → 锁到另一个信号 → **不可逆地跳走了**

## 4. 修复方向（按可行性排序）

### 方案 A: 首次锁后永不重锚（最简单）
- **改动**：一旦 anchor 首次锁定（frames_seen ≥ min_persist_frames 且 area > head_area_floor），**禁用 reanchor**。丢失信号时输出 unknown（而不是换锁别的灯）。
- **优点**：极简，零参数。07 继续正常；02 如果首次锁到行人灯就稳住了；03 如果首次锁错就一直错（但至少一致可解释）。
- **缺点**：依赖"首次锁对"。如果首次锁的是机动车信号（02 的 t=4 就是），整段都错了。
- **风险**：中。需要配合"首次锁对率"评估。

### 方案 B: 多信号并行跟踪 + 行人信号优先规则（推荐）
- **改动**：
  1. `_select_lit` 不再只选一个"最优"头，而是维护**所有持久信号头的列表**（每个独立跟踪）。
  2. 加行人信号先验：行人信号通常在画面**上半部偏左/偏右**（路口近端）、有**竖向排列特征**（走路/站立人图标上下堆叠）。
  3. 当存在多个持久头时，用**位置先验 + 形状先验（lamp_score）+ 相位一致性**综合评分选出行人头。
- **优点**：不依赖首次锁对；能区分行人/机动车信号；可解释性好。
- **缺点**：实现复杂度高；需要定义"行人信号先验"（可能因场景而异）；需要更多调参。
- **风险**：低（渐进改进）。

### 方案 C: 逐视频配置信号位置（工程化兜底）
- **改动**：configs/config.yaml 或 per-video config 里加 `pedestrian_signal_anchor: {cx, cy}` 近似坐标。检测器强制在该位置附近搜索。
- **优点**：100% 可靠（人工确认过位置）；零算法复杂度。
- **缺点**：不泛化；每视频需人工标一次；用户可能不愿意逐个配。
- **风险**：无（作为 fallback 很好）。

### 方案 D: 信号单元形状识别（远期）
- 用 CV 检测"走路人"/"站立人"图标形状 vs 圆形机动车灯泡。
- 需要：模板匹配 / 轮廓分析 / 小型分类器。
- **优点**：从根本上解决"这是不是行人信号"的问题。
- **缺点**：实现量大；图标大小/角度/遮挡变化大；可能需要训练数据。
- **风险**：高（投入产出比待评估）。

### 推荐路径
```
短期(本次会话): A + C 组合
  → 先试方案A（禁重锚），看02/03/04首次锁对率
  → 若首次锁对率 < 50%，叠加方案C（手动配行人信号近似位置）

中期(后续迭代): B（多信号并行跟踪）
  → 在A/C验证可行后，逐步加入自动行人信号识别逻辑
```
