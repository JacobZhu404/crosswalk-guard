# Diag 3 v2 — YOLO-vs-硬GT 命中率验证（指标修正版，read-only）

> **性质**：只读诊断（不改代码、不重挖、不写 configs）。修正 v1 的相机运动污染指标 bug，用 per-frame `true_box_norm` 公平测试。
> **v1 结论已撤销**：v1 "YOLO 框不住行人灯(命中 0–4%)→ 走固定 prior" 被 cc 独立复核推翻（见 `docs/handoff/2026-07-21-cc-verify-diag3-confounded-yolo-viable.md`）。本版复现 cc 公平数字并补充人眼叠框确认。
> **结论先行（与 cc 一致）**：YOLO(yolov8n COCO cls9) **能定位行人信号灯**——中心命中 64%(18/28)、IoU≥0.3 57%(16/28)。近中心 YOLO 框经人眼叠框确认**就是行人灯本身，不是车灯**。但 IoU≥0.5 仅 36%，且 03/05/08 弱视频因灯太小/被遮而全漏或近全漏。→ **架构收敛到"逐帧检测"**（YOLO 作候选 + 时序跟踪补缺口），不走固定 prior、也不裸 YOLO 裁框。

---

## 1. v1 指标 bug（已修）

| | v1 (污染) | v2 (公平) |
|---|---|---|
| 参照框 | 静态 canonical（全视频一个平均位置） | **每帧的 `annotations[].true_box_norm`** |
| 测试集 | 全帧(~4000 帧) | **仅 28 个有真值框的标注帧** |
| 结果 | 命中率 0–4%, meanBestIoU≈0.04 | **中心命中 64%, IoU≥0.3 57%, IoU≥0.5 36%** |
| 根因 | 手持相机运动使灯逐帧位移→静态参照错位→假 miss | 每帧比该帧 GT → 运动不再污染 |

v1 的 "框不住" 是**相机运动的测量伪影**，不是 YOLO 无能。cc 已独立复核并裁定撤销 v1 结论。

## 2. 方法（v2）

- GT：`datasets/light_location_gt.json`（`ped_signal_location_gt_v1`），取每个标注帧的 `true_box_norm`（非 null 的 28 帧）。
- YOLO：`ultralytics.YOLO("models/yolov8n.pt")`，`classes=[9]`（traffic light），`conf=0.05`（低阈）。
- 对每帧加载 `frame_{fi:06d}.jpg`（fi 映射文件名，经验证存在），跑 YOLO → 与**该帧** true_box_norm 比：
  - **中心距** center-dist：最近 YOLO 框中心到 GT 中心的欧氏距离；<0.06 记"中心命中"（更能判"找没找到"，因 IoU 被 YOLO 整灯头框 vs GT 紧框尺寸差压低）。
  - **IoU**：帧内 best-IoU；报 ≥0.3 与 ≥0.5 两档。
- **叠框渲染**：每帧输出 PNG（GT 蓝框 + 全部 YOLO 红框+置信度）到 `data/output/diag3_overlays/`，供人眼确认 ped-vs-vehicle。
- **弱视频单列**：03/05/08（cc 点名）单独报。

## 5. 分析与裁决

### 5.1 YOLO 能否直接当"逐帧检测器"?

| 维度 | 评估 | 说明 |
|---|---|---|
| 定位准确度 | **可用** | 64% 中心命中, 57% IoU≥0.3 — 多数帧能找到灯的位置 |
| IoU 质量 | **中等** | IoU≥0.5 仅 36%; YOLO 框偏大(整灯头) vs GT 紧框 → 中心距更可靠 |
| 车/人混淆 | **低风险** | 叠框确认: 近中心=行人灯, 远处=车灯, 空间分离明显 |
| 尺寸下限 | **有瓶颈** | 05(2.1%宽)/08(1.6%宽) 全漏或近全漏 → yolov8n 对 <2% 帧宽目标不稳 |
| 遮挡鲁棒性 | **差** | 03 被大巴遮挡→零检出; 遮挡时无恢复能力 |
| 帧间稳定性 | **需跟踪补** | 36% 缺口(12/28 帧未中心命中) → 不能裸裁 YOLO 框, 需要时序/跟踪填补 |

**裁决: YOLO 可作逐帧候选检测器, 但不能一锤定音.** 需要:
1. **时序跟踪/平滑**: 用相邻帧的成功检测填补 ~36% 缺口(卡尔曼/光流/简单最近邻).
2. **尺寸兜底**: 对 05/08 类极小目标, 考虑更大模型(yolov8m/s)或从邻近成功帧做模板匹配.
3. **遮挡恢复**: 03 类遮挡帧靠跟踪外推(短窗口内灯不会消失).

### 5.2 架构方向（与 cc 收敛）

| 方案 | 可行性 | 说明 |
|---|---|---|
| 固定 prior 重定位 | ❌ **死路** | 相机手持运动, 单点 prior 跟不住灯(cc 上轮 finding + 本轮 64% 逐帧证据双重否定) |
| 裸 YOLO 裁框 | ❌ **不够** | 36% 缺口 + 尺寸下限 + 遮挡盲区 → 直接裁会丢 1/3+ 帧 |
| **逐帧检测 + 跟踪补缺** | ✅ **方向** | YOLO 候选(64% 命中) + 时序跟踪填空 + Jacob GT 校验微调. 这是 cc 待出的架构计划的基础数据. |

### 5.3 对下一步的建议

1. **YOLO 够格当候选检测器**: 64% 中心命中 + 叠框确认 ped 灯识别正确 → 可以作为逐帧检测管线的前端.
2. **必须加跟踪层**: 36% 缺口靠纯 YOLO 无法闭合; 需要时序平滑(如 observe() 已有的 running-max 聚合逻辑可复用/扩展).
3. **弱视频策略**:
   - 03(遮挡): 跟踪外推可救(短窗口遮挡).
   - 05/08(尺寸): 升模型(yolov8m)或从成功帧模板匹配; 或接受这些视频的检测率较低(训练时可降权/排除).
4. **Jacob 的角色缩小**: 不再需要画 11 视频框来建 prior; 未来只需: (a) 02/10 多灯甄别(如果架构需要区分多个灯), (b) 重挖出 crop 后抽检.
